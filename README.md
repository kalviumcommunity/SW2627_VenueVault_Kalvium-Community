# VenueVault

VenueVault is a Flutter mobile application backed by Firebase for event
equipment booking, inventory, dispatch, and return tracking.

## Repository structure

```text
.
├── lib/                    # Flutter application code
│   ├── core/               # Shared theme and infrastructure
│   ├── features/           # Feature-first UI and domain code
│   ├── app.dart
│   └── main.dart
├── functions/              # Firebase Cloud Functions (TypeScript)
├── firestore.rules         # Firestore security rules
├── firestore.indexes.json  # Firestore indexes
├── firebase.json           # Firebase services and emulators
├── android/                # Generated by Flutter (after setup)
└── ios/                    # Generated by Flutter (after setup)
```

The Flutter app and Firebase Functions are intentionally kept in one
repository. The app is the client; `functions/` contains trusted server-side
operations and must not be moved into `lib/`.

## Local setup

Install Flutter and the FlutterFire CLI first. From the repository root run:

```powershell
flutter create .
flutter pub get
flutterfire configure --project=venue-vault-kalvium-community
```

`flutter create .` generates the missing `android/` and `ios/` platform
directories. `flutterfire configure` registers the mobile apps and generates
`lib/firebase_options.dart` plus the platform Firebase configuration files.
After that, update `lib/main.dart` to use the generated
`DefaultFirebaseOptions.currentPlatform` when web support is enabled.

Install and build the backend separately:

```powershell
cd functions
npm ci
npm run lint
npm run build
```

Run the mobile app with:

```powershell
flutter run
```

The Firebase project is already selected in `.firebaserc`. Do not commit
secrets, local Firebase credentials, or generated build output.
